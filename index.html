the thesis

One brain, many local hands.

The lab separates reasoning from execution. A cloud model holds the plan and makes the hard calls; small local models do the volume work — code, retrieval, embeddings, drafting — with nothing leaving the network unless a decision genuinely needs the brain.

Everything runs under one rule: the two nodes never depend on each other. Either can be wiped and rebuilt on its own, and the system still stands. What sits on top of that base is a set of specialised programs — coding, knowledge work, design, data, and context — that all share the same router, the same enforced boundary, and the same local-first default.

why it runs local

Local-first is a security posture, not a preference.

Running the models next to the data changes what's possible and what's exposed. Iteration stops costing money, latency drops to the network's own speed, and the hardest question in enterprise AI — where did the data go — has a boring answer: it stayed here.

Data sovereignty
Content stays on the network. Nothing is sampled, logged, or trained on somewhere else.
No metering
Bulk generation, embeddings, and iteration cost nothing per token, so agent loops can run long.
Low latency
Models sit beside the data instead of across a public API on the far side of the internet.
Offline resilience
The lab keeps working when the connection doesn't. Cloud reasoning is an enhancement, not a dependency.
Reproducible
Every service rebuilds from a repository. No hidden state, no undocumented setup, no drift.
Enforced boundary
One audited gate decides what may ever reach the cloud — and refuses everything else by default.

the routing layer

The tier router.

A single hook decides where each task goes. Work passes through a PreToolUse interceptor that classifies it and dispatches to the right backend — reasoning to the cloud brain, everything else to a local executor. A stdio tier-enforcer guards the boundary so nothing silently escalates.

Classify
intercept.py reads the pending tool call and scores the work against the tier map.
Route
Reasoning and review stay with Claude over OAuth; heavy generation escalates to a cloud coder; the volume runs on local Gemma 4 executors.
Enforce
A FastMCP stdio tier-enforcer holds the boundary across a six-layer harness.
Return

what the lab builds

Eight programs on one substrate.

Each program is a specialisation with its own crew of models and MCP tools, and each earns its keep the same way — local where it can, cloud where it must, private throughout. Two of them are foundations the rest stand on: a context layer that remembers, and an orchestration layer that decides.

program 01

Claude tier — coding system

A production-grade, local-first coding system: a Claude-only reasoning brain over a six-layer harness, a tier of local Gemma 4 executors for the volume of generation, and a heavyweight cloud coder (qwen3-coder-480b) for the hardest work. The brain plans and reviews; local models write, run, and iterate; the harness decides what is worth escalating.

individuals
Cloud-grade code, but most tokens run free and on-machine — no key sprawl, no meter anxiety on long runs.
businesses
Bounded reasoning spend with an auditable line for where code and data are allowed to travel.

dsr-OMS · Indian omnichannel retail

One operational spine for every order channel.

dsr-OMS normalises orders from marketplaces, ONDC, the brand webstore, stores and warehouses into one canonical workflow. Operators see orders, shipments, routing, inventory, locations, integrations, AI insights and audit history in a single responsive workspace.

The transactional core is deliberately deterministic. It reserves sellable stock, minimises shipment splits, selects eligible fulfilment locations, enforces a four-hour allocation-acceptance SLA, and releases stock before rerouting when a location does not accept on time.

AI inside the guardrails

An operations copilot that advises, never transacts.

AI cannot accept, cancel, reroute, reserve stock, issue refunds or update ERP state. Deterministic services remain authoritative.
  • Reads a masked operational snapshot and returns structured summaries, risks, recommendations and confidence.
  • Uses local Gemma 4 E4B through Ollama by default; approved cloud providers are opt-in through server-side configuration.
  • Flags breached acceptance SLAs, stockout exposure, channel exceptions, and shipment delay or return-to-origin risk for human review.
  • Falls back safely to an explicitly labelled deterministic summary when a model is unavailable or returns invalid output.
  • Audits provider, model, input hash, latency, status and fallback use without recording the full prompt or customer PII.
research · test · build

MCP is the socket. Local is the sandbox.

Local models turn iteration into a free operation. Large agent loops, evaluation runs, and adversarial tests all execute on-machine, so behaviour is validated at volume without a meter running — the difference between reading about an agent's failure mode and reproducing it a thousand times before it reaches anything real.

MCP is the standard socket. Every tool, dataset, and vault plugs into the agents through one protocol, so new capability composes instead of being re-integrated each time. The same harness that runs experiments runs production, which means what you validate is what ships — new behaviour is prototyped on local models, gated through the enforcer, and promoted to the brain only where judgment is genuinely required.

security & resilience

Default closed. Independent by design.

The default is closed. Content leaves the perimeter only when a decision genuinely needs the brain, and that path is explicit — an agent cannot quietly route sensitive work to the cloud, because the tier-enforcer holds the boundary rather than trusting the model to respect it.

Credentials are the usual leak. The brain authenticates over OAuth with no API keys written to disk, removing a whole class of exposure; the nodes reach each other over a private WireGuard mesh behind a Cloudflare Tunnel and are never published directly to the internet.

Independence is the resilience story. The two nodes share nothing, so either can fail without taking the system with it, and recovery is a repository checkout rather than a backup restore. Because every service is reproducible, the worst case is measured in minutes.
